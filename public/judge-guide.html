One shared tab.
Direct BCH paybacks.

TabCash records shared expenses, allocates exact satoshis and reduces the payback list. A connected WizardConnect HD wallet can sign a direct BCH mainnet settlement; keys remain in the wallet. It is a static, client-side app with no first-party backend.

Chain evidence pending. The Sample demo has fictional Austin expenses; My tab starts empty and stores separately in this browser. Sample mode cannot connect a wallet, send BCH or record settlements. No wallet pairing or transaction is simulated here.

A two-minute walkthrough without funds

The page runs top to bottom: hero, How it works, dashboard, Insights, For judges.

  1. Open Sample demo (20 seconds). It is selected by default in the header switch. In the dashboard, read the Austin tab's total and each person's balance.
  2. Add an expense (30 seconds). Choose + Add an expense and enter a tiny fictional amount such as 0.00000010 BCH, split among three people. The remainder is assigned deterministically in satoshis. Recording an expense moves no funds.
  3. Check activity and Insights (30 seconds). Filter the activity list (All, Expenses, Settlements), then scroll to Insights to see where the money went and who pays whom.
  4. Review the settlement flow (20 seconds). Choose Review settlement plan. The greedy matching plan clears balances; it does not promise a globally minimal transaction count. Close the dialog.
  5. Switch to My tab (20 seconds). The empty, separately stored workspace is where real addresses and real settlement live. Export this tab and Import a tab exchange unsigned local expense records.
  6. Optional: Connect wallet. The wallet stack is a separate bundle that loads on first click of Connect wallet, so the first page load stays small. Connecting contacts the external WizardConnect relay.

Optional participant-authorized live segment

Use a dedicated wallet and a real intended recipient. In My tab, add the full bitcoincash: recipient address by clicking the person's name. Connect a compatible WizardConnect HD wallet; fund only the displayed receive address with a small amount of BCH. The app scans the first 20 receive and change addresses, excludes CashToken UTXOs, limits a payment to 546–1,000,000 sats and uses a fixed 1,000 sat miner fee.

Review the exact recipient, amount and change in both app and wallet, tick the mainnet acknowledgment, and authorize only a payment you intend to make. Retain its actual transaction ID, inspect it independently and record confirmation manually. Broadcast acceptance or one server's confirmation report does not itself update the expense ledger. A saved ID with an interrupted broadcast has an unknown outcome; inspect before retrying.

Hosting handoff

  1. Run npm test, npm run build and npm run check:local. The strict npm run check:submission stays blocked while a required field is blank. It checks formats only; independently open each public link and verify address ownership.
  2. Deploy dist/ to any static host at the domain root using the commands in DEPLOY.md. Open the hosted URL in a clean browser and finish the walkthrough, export/import and mobile and desktop layout and keyboard focus.
  3. Check relay and Electrum connectivity and actual wallet interoperability on the hosted origin. The app has no backend or secrets; any CSP must allow the wallet relay and Electrum connections.
  4. Record the demonstration and real transaction evidence only after participant authorization. npm run package:preview makes a clearly marked local-review artifact while public fields are pending.

This page does not claim any of the gates above are complete.
